## 发现

### 1. OpenCode 适配器失效 → 已修复（2026-09-11）
本机安装的是 **OpenCode v1.2.10**，其会话存储已从旧的 `storage/session|message|part` JSON 树迁移为单一 SQLite 库：
`~/.local/share/opencode/opencode.db`（224MB，WAL 模式）。

适配器 `lib/sources/opencode.js` 原本硬编码读取 `storage/session/<proj>/<id>.json`，该目录结构在当前版本已不存在，故初版自测 `scan()` 返回 0 会话。

**修复**：仿照 `zcode.js` 重写 `opencode.js`，改为只读查询 `opencode.db`（同一套 `session → message → part` 三层模型，载荷在 `data` JSON 列）。跳过 reasoning/step-*/agent/compaction/file 类 parts，仅导出 `text`(非 synthetic) 与 `tool`，贴合宿主契约。修复后本机自测 **629 会话**，抽样转换 OK（~100KB，远低于 512KiB 上限）。

- 提交：`fix/opencode-sqlite` 分支 `4ff0290`（本地，未推）。
- 归属 step-2「若有问题及时修复原版本」。发布方式待定——见对话：折叠进 PR #23（让合并的 0.4.4 即正确）还是等 #23 合并后随 0.4.5 发。

### 2. WorkBuddy 超大会话超过宿主 512KiB 上限
抽样中一个 WorkBuddy 会话序列化后约 **9.1MB**，远超宿主 `main.js` `toContractSession` 的 512KiB 契约上限（另含 2000 条消息 / 深度 8 限制）。该限制由宿主施加，适配器本身无 bug；但意味着**超大会话在导入时会被宿主拒绝或截断**。建议在 UI/文档层面提示，或适配器侧对超大会话做分片/摘要（属改进项，非阻塞）。

### 3. Pi 为空属预期
`~/.pi` 本机不存在（Pi 桌面 app 未安装），`scan()` 优雅返回 `[]`，符合设计。真机装有 Pi 时再验。
